# Proposal: ken-home-workspace

## Why

Home was built when Ken opened one project at a time, and it still reads
every card from `app.project` — the single **focused** member. The
workspace refactor and the eight changes after it never revisited it.

With a seven-member workspace open, Home shows one member's digest, one
member's review queue, one member's unread files and recents, under
headings that read like an overview of everything. That is worse than
being incomplete: it is confidently wrong about six-sevenths of the
user's work, with no visible signal that anything is missing.

The pieces needed to fix it already exist and are already flag-on:
`federatedKg` builds `kg.sqlite` at the workspace root, `kgRouting`
plans and merges cross-member searches through `routing.rs`, and
`pipeline::compose_digest` composes a board summary. What is missing is
a surface that uses them, and one stale constraint in `route_search`
that pins it to whichever members happen to be open.

## What Changes

- **`route_search` enumerates from the workspace manifest, not from
  `AppState::members`.** Its doc comment records the deviation — "members
  = every project currently open in `AppState::members` … no
  `workspace.rs` manifest exists yet to enumerate a workspace's members
  independent of what's open this session". `workspace.rs` shipped in the
  workspace change; the deviation is now removable. Targets come from
  `Workspace::members`, and each target's index is opened by project id
  (`Db::open(base, project_id)`) — colocated under the app base dir and
  therefore readable without activating the member, spinning up its
  watcher, engine, or evicting a resident. A dormant member becomes a
  searchable member.
- **Home search becomes workspace search with an explicit scope.** The
  existing Home search box gains a scope control: **All projects** (the
  default) or a single member. All projects routes through
  `route_search`; a named member pins `RoutePlan.targets` to that one id,
  skipping planning. Results render with their member name and the
  `ken://<project-id>/<rel-path>` address `RoutedHit` already carries, so
  every hit says which project it came from.
- **Home digest becomes a workspace digest, composed not replaced.**
  Today's per-project digest generation (`digest.rs`, the `digests`
  table, the ≥07:00 local gate, the quiet-day fallback) is untouched. A
  new workspace layer rolls up each member's stored digest for today plus
  `pipeline::compose_digest`, into one "what changed across your
  projects, what's waiting on you" card. Per-member detail is one click
  down. No member digest is regenerated by this change.
- **A members strip on Home** — one row per manifest member: index state,
  unread count, failed files, and `MemberStatus` (`Ok` / `Missing` /
  `Invalid`) for members whose folder moved or whose `project.json` no
  longer parses. This is the surface that makes a dormant or broken
  member visible instead of silently absent.
- **The daily board spans members.** Home's waiting/needs-attention
  sections read the workspace task board rather than the focused
  member's, matching what `BoardStateDto` already returns.
- **Scope model: one workspace focus, optionally overridden per tab.**
  `app.project` stays the single source of truth for "which member am I
  in". Tabs that benefit from narrowing (Files, Tasks) gain a visible
  scope chip defaulting to *inherit*. No per-tab project state, no
  independent focus per screen.

## Capabilities

### New Capabilities
- `workspace-home`: the workspace-scoped Home — workspace digest,
  cross-member daily board, members strip, and the scope chip contract.
- `workspace-search`: Home search across all members or one, including
  dormant-member reach and per-hit project attribution.

### Modified Capabilities
- `kg-routing`: `route_search` enumerates workspace members from the
  manifest and opens their indexes by project id, rather than searching
  only members open this session.

## Impact

- `crates/ken-core`: a workspace-digest composer (roll-up of per-member
  stored digests + `pipeline::compose_digest`); no change to
  `digest.rs`'s per-project generation, `routing.rs`'s planning, or the
  KG.
- `src-tauri`: `route_search` target enumeration from `Workspace::members`
  with by-id `Db::open`; a workspace-digest command; a members-overview
  command carrying index state / unread / failed / `MemberStatus`.
  `loadFocusedMemberState`'s documented gap (no per-member `ProjectInfo`
  read path, so `excluded`/`ingestRunner` fall back to defaults) is the
  same gap this command closes.
- Frontend: `HomeScreen.svelte` restructured around workspace-scoped
  blocks; `HomeSearch.svelte` gains the scope control; `HomeStatus.svelte`
  becomes the members strip; a scope chip in Files and Tasks; `api.ts`
  types and wrappers.
- Flags: **no new flag.** Each block reuses the flag that already owns
  its data — `workspace` for the members strip and workspace digest,
  `kenTasks` for the daily board, `kgRouting` for cross-member search.
  With all of them off, Home renders exactly as it does today.
- Tests: manifest-driven target enumeration including a dormant and a
  `Missing` member; scope-pinned planning; workspace digest roll-up with
  a member that has no digest today; members strip states; Home renders
  unchanged with flags off.
